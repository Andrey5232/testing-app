\# Общая архитектура экосистемы



\## 1. Обзор

Экосистема состоит из двух независимых веб-сервисов:



| Система | Роль | Разработчик |

|---------|------|-------------|

| \*\*Survey Website\*\* | Клиент — сайт-опросник | Андрей Иванов |

| \*\*BaaS Platform\*\* | Сервис — API аутентификации и профилей | Николай Вареников |



\## 2. Диаграмма взаимодействия

\## 3. Поток данных



1\. Пользователь открывает Survey Website в браузере.

2\. Нажимает «Войти» → вводит email и пароль.

3\. Survey Website отправляет `POST /api/auth/login` на BaaS Platform.

4\. BaaS Platform проверяет данные в БД, генерирует JWT, возвращает `access\_token`.

5\. Survey Website сохраняет токен в localStorage и использует его в запросах профиля.

6\. При прохождении опроса ответы сохраняются в БД опросов.

7\. Статистика отображается пользователю.



\## 4. Протокол взаимодействия



\- \*\*Транспорт:\*\* HTTPS.

\- \*\*Формат:\*\* JSON (REST API).

\- \*\*Аутентификация:\*\* JWT в заголовке `Authorization: Bearer <token>`.



\## 5. Список endpoint'ов API



См. `api-contracts.md` в корне репозитория.



Ключевые:

\- `POST /api/auth/register` — регистрация.

\- `POST /api/auth/login` — вход, возвращает JWT.

\- `GET /api/profile/{id}` — профиль пользователя.



\## 6. Границы ответственности



\- \*\*Survey Website:\*\*

&#x20; - UI/UX, формы, отображение опросов и статистики.

&#x20; - Хранение JWT в браузере.

&#x20; - Отправка API-запросов.

\- \*\*BaaS Platform:\*\*

&#x20; - Регистрация, аутентификация, выдача токенов.

&#x20; - Хранение пользователей и профилей.

&#x20; - Валидация JWT.



\## 7. Взаимодействие с Базой данных



\- У BaaS — своя БД (users, profiles).

\- У Survey Website — своя БД (surveys, questions, responses).

\- Связь между БД — через поле `user\_id`, приходящее из BaaS.
